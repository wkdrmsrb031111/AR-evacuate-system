# AR Evacuate 관리자 웹

건물·층·방 이름을 등록하고 장소마다 출입문 사진 한 장을 로컬 서버에 저장하는 화면입니다.

## 실행하기 (Windows / VS Code 터미널)

먼저 프로젝트 최상위 폴더의 `로컬서버_실행.cmd`로 API 서버를 켜세요. 이어 `관리자웹_실행.cmd`로 웹을 켤 수 있습니다. VS Code 터미널에서는 아래 명령을 `admin-web` 폴더에서 실행합니다.

```powershell
npm.cmd install
npm.cmd run dev
```

터미널의 Local 주소를 브라우저에서 여세요. 종료는 `Ctrl+C`입니다.

## 오늘 확인할 것

1. 건물 `본관`, 층 `2층`, 방 `제3회의실`을 입력하고 **장소 등록**을 누르세요.
2. 오른쪽 목록에 등록한 장소가 나타나는지 확인하세요.
3. 같은 건물·층·방을 한 번 더 입력하면 중복 등록 안내가 나타납니다.
4. 새로고침한 뒤에도 목록이 유지되는지 확인하세요.

현재 데이터는 `server/data/evacuate.sqlite3`에 저장됩니다. 브라우저 데이터를 지워도 서버 DB는 유지됩니다. 서버 DB와 가상환경은 Git에 올리지 않습니다. 앱·다른 PC의 네트워크 연결은 아직 구성하지 않았습니다.

기존 브라우저 데이터가 있으면 **기존 데이터 서버로 복사**를 누릅니다. 장소 ID·사진·삭제 상태를 함께 복사하고 브라우저 원본은 유지합니다. 이후에는 서버 데이터만 수정하며 브라우저 원본은 최신 상태로 갱신하지 않는 이전 버전의 백업입니다. 이미 존재하는 서버 ID와 사진은 복사 재시도 시 덮어쓰지 않습니다.

## 장소 수정·삭제

- 목록의 **수정**을 누르면 왼쪽 입력창에서 건물·층·방 이름을 바꿀 수 있습니다. **수정 내용 저장**으로 반영하고 **수정 취소**로 빠져나옵니다. 장소 ID를 유지하므로 기존 사진도 유지됩니다.
- 목록의 **삭제**를 누르면 확인창이 표시됩니다. 삭제한 장소는 일반 목록과 사진 선택 목록에서 숨겨집니다.
- **삭제한 장소**를 펼쳐 **복원**을 누르면 장소와 연결된 사진을 다시 볼 수 있습니다. 이 단계에서는 사진 파일을 영구 삭제하지 않습니다.
- 다른 활성 장소와 이름이 겹치는 수정·복원은 서버에서도 막습니다. 삭제 상태와 사진도 서버에 유지됩니다.

## 출입문 사진 사용 방법

1. 화면 아래 **출입문 사진 등록**에서 사진을 연결할 장소를 선택하세요.
2. JPG·PNG·WebP 파일(최대 15MB)을 선택하세요. HEIC는 JPG 변환이 필요합니다.
3. 미리보기를 확인하고 **사진 저장**을 누르세요. 선택만 하면 저장되지 않습니다.
4. 장소를 바꾸면 해당 장소의 사진을 확인할 수 있습니다. 새로고침 후에도 유지됩니다.

사진은 긴 변 1,600px 이하의 JPG로 변환해 API 서버로 전송합니다. 서버에서 다시 이미지 유효성을 확인하고 SQLite에 저장합니다. 사진 교체는 새 저장이 성공한 경우에만 반영되고, 저장 전 선택 취소가 가능합니다. 기존 IndexedDB의 사진은 복사 시 읽기만 하며 삭제하지 않습니다.

## 장소 사이의 이동 경로 연결

화면 아래 **이동 경로 관리**에서 같은 건물·층의 인접한 두 장소를 선택하고 거리(m), 가는 길과 오는 길의 안내를 각각 입력하세요.
하나의 연결은 양방향입니다. 같은 두 장소를 반대 순서로 다시 등록할 수 없습니다. 연결 수정, 삭제, 삭제한 연결 복원이 가능하며 서버에 저장됩니다.
삭제한 장소와 연결된 구간은 앱 조회에서 숨겨지고 장소 복원 시 다시 표시됩니다. 활성 연결이 있는 장소의 건물·층을 바꾸려면 연결부터 삭제해야 합니다.
이름과 장소 종류는 연결을 유지한 채 수정할 수 있습니다. 층간 이동은 아직 지원하지 않습니다.

## 가장 가까운 비상계단 입구 계산

**경로 계산 미리보기**에서 출발 장소를 선택하고 **가장 가까운 계단 찾기**를 누릅니다.
같은 건물·층의 활성 장소와 연결만 사용해 구간 거리의 합이 가장 짧은 비상계단 입구(`stairs`)를 찾습니다.
도착 장소, 총 거리, 이동 순서, 이동 방향에 맞는 구간 안내를 표시합니다. 출발지가 계단 입구이면 0m입니다.
등록된 계단이 없는 경우와 계단은 있지만 경로가 끊긴 경우를 구분하며, 삭제한 장소·연결은 제외합니다.
한 번 계산한 뒤 장소나 연결·통행 상태를 변경하면 예전 결과를 지우고 자동으로 다시 계산합니다. 출발지를 바꾸거나 페이지를 새로고침한 뒤에는 계산 버튼을 눌러야 합니다. 다른 PC에서 수정한 내용은 목록 새로고침·페이지 새로고침 후 반영되며 별도 실시간 푸시는 없습니다.
관리자가 등록한 통행 불가 구간을 반영하며 화재·연기·실제 통행 가능 여부를 자동 판단하지 않는 시연용 계산입니다.

## 다음 단계

장소 등록·수정 시 종류(일반 장소 / 복도·갈림길 / 비상계단 입구 / 건물 밖 출구)를 선택할 수 있습니다.
기존 장소는 일반 장소로 유지되며 장소 ID와 사진은 바뀌지 않습니다. 종류는 서버에 저장되고 앱 API의 `kind` 필드로 전달됩니다.
장소 종류만으로 경로가 생성되지는 않습니다. 장소 사이의 연결과 거리를 등록해야 계산할 수 있습니다.

다음에는 휴대폰 연결과 AI 표지판 인식을 진행할 예정입니다. 로그인과 실제 화재 감지는 아직 구현하지 않았습니다. 상세 서버 실행·백업·API·테스트 방법은 `../server/README.md`를 참고하세요.

## 통행 불가 구간과 우회

등록된 연결에서 **통행 불가 등록**을 누르고 사유를 작성해 저장하면 양방향 모두 경로 계산에서 제외합니다. 계산된 경로가 있으면 자동으로 다시 계산하며, 다른 계단으로 바뀐 경우 목적지 변경을 표시합니다. 같은 계단으로 돌아가는 우회도 가능합니다. 모든 경로가 끊기면 경로가 없다고 표시합니다.

**통행 가능으로 변경**하면 상태·사유·등록 시각이 해제되고 다시 계산에 포함합니다. 상태는 새로고침·서버 재시작 후에도 유지됩니다. 연결 수정이나 삭제 후 복원은 통행 불가 상태를 해제하지 않습니다. 관리자가 직접 등록하는 기능이며 실제 상황 자동 감지가 아닙니다.


## 시연 준비 점검

화면 아래 **시연 준비 점검하기**를 누르면 모든 활성 일반 장소(`kind=room`)의 계단 경로를 점검합니다. 계산 가능한 곳, 계단 입구 미등록, 연결된 경로 없음(통행 불가 포함)을 구분하고 목적지·거리·우회 여부를 보여줍니다. 사진 미등록은 모든 활성 장소를 대상으로 별도 집계합니다. 사진이 없어도 경로 계산은 가능하며, 사진 내용의 정확성은 검사하지 않습니다.

장소·연결·통행 상태·사진을 수정하면 이전 점검 결과를 숨기고 재점검을 안내합니다. 결과는 서버에 기록하지 않는 조회 기능이며, 다른 PC의 변경은 재점검 시 반영됩니다. 실제 대피 안전성이나 앱·카메라의 동작 여부를 검증하는 기능은 아닙니다.


## 간단한 관리자 화면 사용법

위쪽 작업 메뉴에서 한 영역씩 선택합니다.

- **장소·사진 → 장소 관리**: 장소 카드 목록, 건물 선택·검색, 새 장소 추가, 수정·삭제·복원. 입력창은 추가·수정 시에만 엽니다. 카드의 사진 관리 버튼은 해당 장소의 사진을 바로 엽니다.
- **장소·사진 → 사진 관리**: 장소 선택, 사진 미리보기·저장. 촬영 안내와 파일 정보는 펼쳐 확인합니다.
- **길·통행**: 등록된 길의 통행 상태가 먼저 보입니다. 새 길 연결 버튼으로 입력창을 열며, 통행 상태별로 목록을 볼 수 있습니다. 안내 문장과 수정·삭제는 길 정보 보기·수정에서 확인합니다.
- **확인·점검 → 대피 경로 확인**: 출발지 선택과 최단 경로·우회 결과.
- **확인·점검 → 등록 정보 점검**: 경로·사진 누락 확인. 보완 버튼은 관련 작업 화면으로 이동합니다.

오른쪽 위 **큰 글씨 보기**로 글자 크기를 키울 수 있습니다. 설정은 해당 브라우저에 저장됩니다. 주요 버튼은 최소 48px 높이로 제공하며 색상과 상태 문구를 함께 표시합니다. 작업 메뉴는 좌우 방향키·Home·End로 이동할 수 있고, 본문 바로가기와 키보드 초점 표시를 제공합니다.

레이아웃은 320px·390px·1280px 폭에서 확인했습니다. 화면 전환 중 입력·계산 상태는 유지하며 서버 API·데이터 구조는 변경하지 않았습니다. 모든 연령대의 실제 사용자 사용성 검증을 완료했다는 뜻은 아닙니다.


## 등록 정보 백업

화면 아래 **등록 정보 백업**을 펼치고 **백업 파일 저장**을 누르면 현재 서버에 저장된 정보가 ZIP으로 다운로드됩니다. 장소·사진·연결·통행 불가 상태와 삭제 기록까지 포함합니다. 브라우저에서 아직 저장하지 않은 입력과 사진, 앱 소스 코드는 포함하지 않습니다.

ZIP에는 `data.json`, `photos/`, `database/evacuate.sqlite3`, `README.txt`가 들어 있습니다. 복원 기능은 아직 제공하지 않습니다. 다운로드 버튼은 저장소 연결·기존 데이터 복사가 완료되어야 사용할 수 있습니다.
