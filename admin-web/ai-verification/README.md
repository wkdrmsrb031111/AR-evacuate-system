# 표지판 AI 기술 검증 — 2026-11-24

## 검증 범위와 결론

Tesseract.js 7과 한국어·영어 모델을 사용해 실제 OCR을 실행했다. 표지판 글자 인식은 시제품에 적용할 가능성이 있다. 현재 결과만으로 자동 위치·방향 확인이 가능하다고 결론내릴 수는 없다.

## PC 검증

`node scripts/verify-sign-ai.mjs`로 실행한 탐색적 결과는 benchmark.json에 보관한다. 생성된 예제 사진 3장 각각의 전체 사진과 사람이 고른 표지판 영역을 사용했다. 일반적인 정확도 시험이나 실환경 표본이 아니다.

| 사진 | 전체 사진에서 기대 이름 일치 | 표지판 영역에서 기대 이름 일치 |
| --- | --- | --- |
| ai 듣기 | 실패 | 실패 ('22\| 듣기'로 일부 오인식) |
| 복도 갈림길 | 실패 | 성공 |
| 동쪽 비상계단 | 실패 | 성공 (띄어쓰기 제거 후 비교) |

Node 실행 중 엔진의 언어 파일 경고가 출력됐다. 해당 수치는 탐색적 결과로만 취급한다. 별도로 실제 브라우저 Web Worker에서도 확인했다.

- PC 브라우저에서 예제 복도 사진의 지정 영역을 3배 확대해 OCR 실행.
- 인식 텍스트 '복도 갈림길', 입력 이름과 일치 확인.
- 모델 준비와 예제 로드를 포함한 총 2.8초. 갤럭시 속도로 해석하면 안 된다.
- 모델이 내놓는 confidence는 실제 정확도나 안전도 점수가 아니다.
- 공개 HTTPS 주소에서도 실제 OCR을 실행해 '복도 갈림길' 일치 확인. 해당 PC 브라우저 실행은 모델 다운로드·준비를 포함해 총 9.6초. 실기기 성능 수치가 아니다.

## 갤럭시에서 검증할 항목

공개 카메라 페이지의 '표지판 AI 검증'에서 진행한다. 처음에는 모델 파일 다운로드가 필요하다. 이미지·영상은 브라우저에서 처리하며 업로드하지 않는다.

1. 실제 표지판에 적힌 이름을 입력한다.
2. 카메라 중앙 상자 안에 글자 한 줄이 크게 들어오게 맞춘다.
3. '현재 카메라 화면 AI 확인'으로 한 장을 캡처해 인식한다.
4. 읽힌 글자, 일치 여부, 시간, AI가 읽은 영역을 비교한다.
5. 같은 표지판의 정면·약간 기울어진 상태·조금 먼 거리에서 각각 시험한다.
6. 다른 이름을 입력하거나 다른 표지판을 비췄을 때 일치하지 않는지도 확인한다.

실기기 결과는 아직 수집 전이다. 실제 표지판 인식의 반복 성공과 실패 사례를 확인한 뒤 연속 프레임 확인으로 진행한다.

## 방향 자동 확인에 대한 한계

글자가 일치해도 해당 문을 유일하게 식별하거나 휴대폰의 방향을 알아낸 것은 아니다. 같은 이름의 표지판·종이·화면도 인식할 수 있다. 그래서 이 검증 기능은 경로 안내의 '기준 방향 확인'을 자동 체크하지 않는다. 방향 자동 확인에는 등록된 시각 기준과 카메라 자세 정렬을 추가 검증해야 한다.

## 기준 표지판 일치 → 화살표 표시 시험 기능

구간별 선택 필드 facingSignText를 관리자 안내 파일에 추가했다. 등록된 이름은 카메라 화면에서 임의로 수정할 수 없다. 사용자가 AI 확인을 한 번 누르면 실제로 갱신된 두 카메라 프레임에서 각각 전체 이름이 일치해야 화살표 표시를 허용한다. 이름 정규화는 공백·기호 제거와 영문 소문자 변환이다. 부분 일치, 다른 호실, 예제 이미지, 미등록 기준은 거절한다. 이미지를 제출한 후 카메라·경로·구간·수동 확인 상태가 바뀌면 늦은 결과는 사용하지 않는다.

이 기능은 체크박스를 조작하는 대신 별도의 'AI 표지판 일치' 상태를 사용한다. 화면에 방향을 측정한 결과가 아니라고 표시한다. 자동 위치 추적·바닥 고정 AR·연속 스캔·자동 도착 감지는 구현하지 않았다. 실제 표지판의 배치에 맞게 기준과 방향을 함께 등록해야 한다.

판정·파일 테스트 총 12개 통과, 웹 빌드 통과. PC 브라우저에서 예제 사진의 OCR 일치 후에도 화살표가 나타나지 않고 도착 버튼이 비활성으로 유지됨을 확인했다. 실제 카메라의 두 프레임 일치→화살표 표시 전체 흐름은 갤럭시에서 추가 확인해야 한다.
