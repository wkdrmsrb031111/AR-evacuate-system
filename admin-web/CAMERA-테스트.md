# 카메라 화살표 테스트

PC 화면: http://127.0.0.1:5173/camera.html

갤럭시 HTTPS 화면 (로그인 없음): https://ar-evacuate-camera-test.workspace-815047.chatgpt.site/

실시간 카메라 영상 위에 직진·왼쪽·오른쪽 화살표를 표시하는 웹 화면이다. 이제 관리자에서 계산한 경로의 안내 파일을 가져오면 구간별 등록 방향을 표시한다. 진행 위치와 휴대폰 방향은 자동 추적하지 않으며, 복도 바닥에 고정되는 공간 AR은 아니다.

## 경로 연결 — 파일 방식

1. 관리자 웹 → 확인·점검 → 대피 경로 확인에서 경로를 계산한다. OCR 후보에서 경로를 선택해도 된다.
2. 결과 아래 **카메라 안내 파일 만들기**를 펼친다.
3. 각 구간의 출발점에서 바라볼 기준과, 그 기준에서의 직진·왼쪽·오른쪽을 직접 입력한다. 설명 문장에서 방향을 추측하지 않는다.
4. **카메라 안내 파일 저장**으로 camera-route.json을 받는다.
5. 파일을 휴대폰에 옮긴 뒤 공개 카메라 사이트의 **안내 파일 가져오기**에서 선택한다. 파일은 브라우저 안에서 읽으며 업로드·영구 저장하지 않는다.
6. 카메라를 켜고, 현재 구간의 기준을 바라본 다음 **기준 방향을 바라보고 있어요**를 체크한다. 이때 해당 구간의 화살표를 표시한다.
7. 도착 장소를 직접 확인하고 **도착 확인**을 누르면 다음 구간으로 넘어간다. 마지막 계단 도착 확인 후 화살표를 숨긴다. 카메라를 껐다 켜거나 다른 앱으로 이동하면 방향 확인도 초기화한다.

가져온 경로는 계산 시점의 스냅샷이다. PC 통행 상태 변경이 실시간 전달되는 구조는 아직 아니다. 변경 후 새 경로를 계산·저장해서 다시 가져와야 한다. 파일에 계산 시각을 표시한다.

**가상 회사 예제로 시작**은 기존 서버에서 계산한 가상 회사 20m 경로를 사용한다. 직진→오른쪽은 동작 확인을 위해 지정한 시연 방향이며 실제 건물 방향을 검증한 데이터가 아니다. 지금 있는 건물에서 이 방향대로 걷지 않는다.

안내 파일 검증 테스트 6개와 웹 빌드 통과. PC에서 예제 경로 불러오기, 기준 확인 전 화살표 숨김, 직진→오른쪽 전환, 마지막 도착 확인 후 화살표 제거를 확인했다. 경로 기반 새 기능의 갤럭시 동작은 사용자 확인이 필요하다. 이전 버전의 실시간 카메라와 수동 화살표는 사용자가 갤럭시에서 작동을 확인했다.

## 표지판 AI 검증 추가

일반 검증에서는 실제 이름을 입력한 뒤 한 장의 인식 결과를 확인한다. 기준 표지판이 등록된 경로에서는 이름을 수정할 수 없다. **현재 카메라 화면 AI 확인**을 한 번 누르면, 갱신된 카메라 프레임 두 장에서 등록 이름이 각각 전체 일치하는지 확인한다. 성공 시 수동 체크 없이 해당 구간 화살표를 표시한다. 예제 사진 인식 결과는 자동 표시 조건으로 사용하지 않는다.

자동 표시는 표지판 글자 일치를 이용한 시제품 기능이다. 위치나 카메라 자세를 측정한 결과가 아니다. 카메라 정지·재시작, 구간 변경, 경로 재선택 때 결과를 초기화하고, 이전 작업의 늦은 응답은 무시한다. 아직 AI 확인 버튼과 도착 확인은 사용자가 누르며 연속 영상 자동 탐지는 아니다.

관리자 웹의 **카메라 안내 파일 만들기**에서 각 구간의 **기준 표지판 글자**를 선택적으로 입력한다. 해당 표지판을 정면으로 봤을 때의 이동 방향과 바라볼 기준을 현장에서 일치시켜 등록해야 한다. 표지판 이름을 넣지 않은 기존 파일은 수동 확인 방식으로 계속 사용할 수 있다.

가상 회사 예제에는 '복도 갈림길'과 '동쪽 비상계단'을 각각 AI 연결 시연용 기준으로 지정했다. 방향은 가상 데이터이므로 실제 건물에서 따라 걷지 않는다. 이름을 크게 쓴 종이로 AI→화살표 표시 연결만 시험할 수 있다.

판정·파일 검증 테스트 12개 및 웹 빌드 통과. 실제 갤럭시의 두 프레임 인식→화살표 표시 전체 흐름은 사용자 확인이 필요하다. 상세 결과와 한계는 [AI 검증 기록](ai-verification/README.md)에 있다.

## 기본 카메라 사용 방법

1. 관리자 웹과 같은 Vite 서버를 실행한다. API 서버는 이 테스트 화면에 필요하지 않다.
2. 카메라 사용이 가능한 HTTPS 또는 localhost 주소에서 camera.html을 연다.
3. 카메라 켜기를 누르고 해당 사이트의 카메라 권한을 허용한다.
4. 주변 영상 위에 화살표가 겹쳐지는지 확인하고 세 방향 버튼을 시험한다.
5. 카메라 끄기 또는 다른 앱으로 이동 시 카메라가 정지하는지 확인한다.

영상은 저장·업로드하지 않는다. 후면 카메라를 우선 요청한다. PC에 카메라가 없거나 권한이 거부되면 오류를 표시한다.

## Galaxy USB 연결 준비

PC Chrome의 USB 포트 전달 기능으로 접속하면 Wi-Fi 공유나 자체 서명 인증서 없이 localhost로 테스트할 수 있다.

1. 갤럭시를 데이터 전송이 가능한 USB 케이블로 PC에 연결한다.
2. 휴대폰 설정 → 휴대전화 정보 → 소프트웨어 정보 → 빌드번호 7회 터치로 개발자 옵션을 표시한다.
3. 설정 → 개발자 옵션 → USB 디버깅을 켜고, 이 PC의 디버깅 접근 허용 여부를 휴대폰에서 직접 확인한다. 이 기능은 PC가 휴대폰의 개발 테스트에 접근하도록 허용한다.
4. PC Chrome에서 chrome://inspect/#devices를 열고 Discover USB devices를 확인한다. 휴대폰 이름이 표시되는지 확인한다. 인식되지 않을 경우 케이블·휴대폰 설정·제조사 USB 드라이버 등을 추가 확인해야 한다.
5. Port forwarding에서 휴대폰 포트 5173을 PC의 localhost:5173에 연결하고 Enable port forwarding을 켠다.
6. 갤럭시 Chrome에서 http://localhost:5173/camera.html을 연다.
7. 테스트 후 포트 전달과 필요 없는 USB 디버깅 접근을 해제한다.

케이블만 연결한 상태에서는 휴대폰의 localhost가 PC로 연결되지 않는다. 실제 포트 전달 설정이 먼저 필요하다. 현재 PC의 Vite는 127.0.0.1로만 열려 있고 방화벽은 변경하지 않았다.

- PC 브라우저에서 세 방향 표시 및 좌·우 버튼 전환 확인.
