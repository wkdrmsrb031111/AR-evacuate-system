# 표지판 인식 첫 테스트

관리자 웹 → 확인·점검 → 표지판 인식 테스트.

1. 예제 사진 사용 또는 직접 사진 선택.
2. 사진에서 표지판 글자 한 줄이 초록 상자 안에 오도록 영역 조절.
3. 글자 인식 시작.
4. 현재 건물·층 선택 후 읽힌 글자와 등록 장소 후보 비교.
5. 실제 장소와 맞는 후보의 **대피 경로 보기** 버튼 선택.
6. 도착할 비상계단 입구, 총 거리, 구간별 이동 순서 확인. 최신 상태가 필요하면 **경로 다시 확인** 선택.
7. 각 이동 구간의 **다음에 찾아갈 장소** 사진을 확인한다. 사진을 불러오지 못해도 장소 이름과 이동 설명은 유지된다.

Tesseract.js 7을 브라우저 Web Worker에서 실행한다. 한국어·영어 모델과 WASM은 이 PC에서 제공하며 사진을 서버에 업로드하거나 유료 AI API를 호출하지 않는다. `npm install` 후 `npm run dev` 또는 `npm run build`를 실행하면 scripts/prepare-ocr.mjs가 필요한 파일을 public/ocr에 복사한다. 해당 폴더는 생성물이므로 Git에서 제외한다. npm 패키지 설치에는 인터넷이 필요하다.

## 실제 확인 결과 (2026-11-24)

- 웹 빌드 성공. 기존 서버 테스트 34개 통과.
- PC 브라우저에서 실제 OCR 실행 확인.
- 생성된 demo-room.png 전체 사진: 배경 오인식이 많고 장소 일치 실패.
- 같은 사진의 표지판 부분 선택: '듣기' 인식, 'ai' 오인식. 이름 전체 일치는 실패.
- '듣기'와 일치하는 등록 장소 'ai 듣기'를 일부 글자 일치 후보로 표시. 후보를 실제 위치로 확정하지 않는다.
- 일부 일치는 같은 단어가 들어간 다른 장소도 제시할 수 있다. 인식률 검증이나 위치 정확도 보장이 아니다.
- 갤럭시 실기기, 실시간 카메라, AR 안내 및 모바일 성능은 아직 검증하지 않았다.

## 후보 → 경로 연결 확인 (2026-11-24)

- 실제 OCR 결과의 일부 글자 일치 후보를 사용자가 선택한 후 기존 경로 API 호출.
- 가상 회사 2층: ai 듣기 → 복도 갈림길 → 동쪽 비상계단, 20m / 2구간 표시 확인.
- 건물·층 변경 시 기존 경로 제거 확인. 새 후보를 다시 선택해야 계산한다.
- 미래관 5층: 계단 미등록 안내 표시 확인. 이전 건물의 20m 경로가 남지 않음.
- 사진 선택, 인식 영역 변경, 재인식 시 선택한 출발점을 초기화한다.
- 웹 빌드 검사 통과. 경로 계산은 등록된 데이터에 근거하며 실제 위험을 감지하지 않는다.
- 각 구간의 도착 장소 사진을 기존 읽기 전용 사진 API에서 표시한다. 복도 갈림길 사진의 실제 로딩(1448×1086) 및 화면 표시 확인. 테스트 사진은 생성 이미지이며 실제 현장이 아니다.

## 다음 단계

실제 표지판을 가까이 찍은 사진 여러 장으로 같은 테스트를 진행한다. 같은 사진을 반복해서 인식한 결과를 다양한 환경의 정확도로 계산하지 않는다. 한국어·영어 혼합 인식이 계속 부족하면 모바일 전용 OCR과 비교한 후 앱 적용 방식을 정한다. 기기를 빌린 다음 별도로 연결 환경을 준비한다. 현재 웹과 서버는 PC의 127.0.0.1에서만 열린다.

이 화면은 AI 인식 가능성을 확인하는 개발 도구이며 실제 대피 안내용 완성 앱이 아니다.
